Design Cloud Engine（DCE）是专为企业内部 HPC/EDA 研发场景打造的统一入口与管理平台。通过统一 Portal API 与现代化 Web 控制台，为科研与工程设计人员提供便捷的应用启动、作业监控与控制、文件管理及远程图形/命令行会话连接。

> [!NOTE]
> **DCE 的核心定位是不侵入、不替代外部调度器**。它作为接入层与管理编排中枢，负责多集群统一门户与接入治理，底层的排队计算与物理资源分配依然交由 LSF、Slurm 等业界标准调度器完成。

---

## 核心产品边界

| DCE 负责 | 外部专业系统负责 |
|---|---|
| **统一接入**：Web 门户、Portal API、统一鉴权与三员管理 | **排队调度**：外部作业队列与节点算力/内存/GPU 资源调度 |
| **应用中心**：应用模板、参数校验与跨调度器作业提交入口 | **生命周期**：调度器内核中的作业执行状态机与优先级重排 |
| **远程桌面**：协议代理隧道（VNC / RDP / SSH）与会话管控 | **协议服务**：计算节点上实际运行的 VNC Server / xrdp / sshd |
| **文件管理**：文件浏览器、安全传输、大文件流式上下行与删除回收 | **存储基建**：底层 NFS / Lustre / GPFS 并行文件系统配额与权限 |
| **集群编排**：节点自动注册、TLS 双向证书轮换与 Agent 守护 | **机房网络**：物理交换机、VLAN 隔离、防火墙规则与企业 PKI 体系 |

## 关键术语与概念

- **Engine**：系统的主执行程序。Linux 节点可按配置同时以 Server 或 Agent 模式运行；Windows 节点仅作为 Agent 计算节点运行。
- **Portal**：面向最终用户和 Web 前端的 HTTP/WebSocket 服务层，提供业务 API 与轻量嵌入式 Web 控制台。
- **Control**：集群编排管理中心（基于 gRPC），维护全节点拓扑连接，负责任务下发、状态收集与证书签发。
- **Agent**：常驻于各个工作节点的客户端代理，与 ControlServer 保持长连接心跳，负责主机指标采集与任务执行。
- **dc-exec (`dc-exec`)**：特权守护辅助程序。以独立子进程运行，执行诸如切换用户执行脚本、文件提权访问等系统高权限动作。

## 文档阅读指引

为不同角色的工程师推荐的阅读与使用路径：

1. **部署与系统运维工程师**：
   - 阅读 [安装与首次部署](/docs/deployment/install) 了解环境要求与部署步骤。
   - 参考 [配置文件详解](/docs/deployment/config) 规划节点角色与网络拓扑。
   - 参考 [高可用集群部署](/docs/deployment/cluster-ha) 与 [证书与传输安全](/docs/deployment/tls) 搭建生产级集群。
   - 日常使用查阅 [服务管理与日常运维](/docs/deployment/operations) 及 [故障排查手册](/docs/deployment/troubleshooting)。

2. **前端与三方系统集成开发者**：
   - 阅读 [Portal API 契约](/docs/api) 了解全套 RESTful API 与 WebSocket 交互协议。
   - 关注 [用户与会话 API](/docs/api/user) 及 [管理员/三员管理 API](/docs/api/admin)。

3. **内核与系统研发工程师**：
   - 深入阅读 [总体系统架构](/docs/overview/architecture) 建立全景认知。
   - 探索 [核心架构与领域设计](/docs/architecture)（集群通信、特权执行、远程代理与领域模型）。
   - 遵循 [开发者指南](/docs/development) 搭建本地环境、遵循开发规范与门禁验证流程。
