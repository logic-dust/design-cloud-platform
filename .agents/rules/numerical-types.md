# 数值类型约束

- **资源容量**：内存、磁盘等容量数据使用 `int64`，避免 32 位溢出及无符号差值下溢。时间戳与时长遵循各自源契约，不强制统一类型。
- **DB 标识**：GORM 实体主键/外键遵循当前模型与驱动契约；不为类型风格单独引入破坏性 DDL。
- **索引与计数**：Go 切片索引、循环计数和标准库原生 `int` 值保持 `int`，避免无意义的转换链。
- **跨层转换**：先核实 Proto、Model、系统调用与业务层的实际类型，只有边界要求时转换；避免为了表面一致而更改协议或持久化类型。
- **既有存储字段**：没有溢出、缺陷或性能依据时，不做破坏性字段类型迁移。
